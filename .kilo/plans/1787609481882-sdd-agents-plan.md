# Plano: Agentes SDD para Controle Financeiro

## Contexto

O projeto Controle Financeiro usa **Django (Python)** com arquitetura baseada em services/selectors/models/views. O fluxo SDD já está documentado em `docs/specs/000-sdd-baseline.md` e `docs/specs/009-gitflow-pr-issue-standard.md`.

O arquivo `prompts-fluxo-sdd-tdd.md` (do projeto classificador-conta-contabil) contém prompts que podem ser adaptados, mas **alguns são específicos de frontend React** e não se aplicam aqui.

## Análise de Adequação dos Agentes

| Agente | Adequação | Observação |
|--------|-----------|------------|
| `spec-issue-generator` | ✅ Aplicável | Essencial para gerar issues a partir das specs numeradas |
| `task-reviewer` | ✅ Aplicável | Necessário para revisar issues antes da implementação |
| `tdd-implementer` | ✅ Aplicável | Core do fluxo - implementa com RED→GREEN→REFACTOR |
| `frontend-implementer` | ⚠️ Adaptar | O projeto usa Django templates, não React. Renomear para `django-implementer` |
| `pr-preparator` | ✅ Aplicável | Prepara PRs seguindo template do projeto |
| `homologation-validator` | ✅ Aplicável | Valida funcionalidades em ambiente de homologação |
| `spec-updater` | ✅ Aplicável | Atualiza specs quando decisões mudam |

## Agentes a Criar (7 arquivos)

### 1. `spec-issue-generator.md`
- **Modo**: subagent
- **Propósito**: Gerar issues pequenas a partir de specs numeradas
- **Referências**: `docs/specs/000-sdd-baseline.md` (Issue SDD Checklist)
- **Template de issue**: Segue campos obrigatórios do baseline

### 2. `task-reviewer.md`
- **Modo**: subagent
- **Propósito**: Revisar issues antes da implementação
- **Saída**: escopo, testes, riscos, arquivos prováveis, perguntas bloqueantes

### 3. `tdd-implementer.md`
- **Modo**: subagent
- **Propósito**: Implementar issues com TDD
- **Comandos obrigatórios**: `python manage.py check`, `makemigrations --check --dry-run`, `test`
- **Estrutura**: services.py, selectors.py, models.py, views.py, tests/

### 4. `django-implementer.md` (adaptado de frontend-implementer)
- **Modo**: subagent
- **Propósito**: Implementar issues de templates/views Django
- **Validações**: typecheck (mypy), lint (ruff), testes de view/template
- **Estrutura**: templates/, static/css/app.css, views.py

### 5. `pr-preparator.md`
- **Modo**: primary
- **Propósito**: Preparar PRs em Markdown ou draft no GitHub
- **Referência**: `.github/PULL_REQUEST_TEMPLATE.md` (quando criado)

### 6. `homologation-validator.md`
- **Modo**: subagent
- **Propósito**: Preparar validação de homologação
- **Foco**: checklist objetivo, comandos de validação, evidências

### 7. `spec-updater.md`
- **Modo**: subagent
- **Propósito**: Atualizar specs quando surgem novas decisões
- **Regra**: NÃO implementa código, apenas atualiza documentação

## Validações Antes de Criar

- [ ] Projeto usa Django (Python), não React/Vite
- [ ] Specs seguem padrão numerada (000, 001, 002...)
- [ ] Issues seguem campos obrigatórios do baseline
- [ ] Comandos de validação: `check`, `makemigrations --check --dry-run`, `test`
- [ ] Estrutura: services.py, selectors.py, models.py, views.py, tests/

## Riscos e Mitigações

| Risco | Mitigação |
|-------|-----------|
| Agentes gerarem código fora do escopo | Incluir boundaries explícitas em cada agente |
| Prompts em inglês vs português | Manter prompts em português (padrão do projeto) |
| Divergência entre agente e baseline | Referenciar baseline em todos os agentes |
